# 制限事項

## 通信・再現範囲（従来の検証から引き継ぐ制限）

- 検索URLはAPKの静的解析で確定できる範囲のみを再現している。
  端末・実行時依存のパラメータ（cuid、cua、from、pkgname、
  p_sv、ネットワーク状態系など）は付けない。これは検証済み
  プローブと同じ条件であり、実機の全リクエストと完全一致する
  保証はない。
- ant_ct の時刻は「現在Unix時刻の秒、校正オフセット mDelta=0」
  の近似。サーバ側の校正値そのものは観測できない。
  なお HTTP 200 が返ること自体はサーバ側で ant_ct が検証された
  証拠にはならない（過去ラウンドで明記のとおり）。
- User-Agent の端末固有部分は代表値（検証プローブの定義どおり）。
- 対象は当APKのWeb検索（web テンプレート）のみ。縦検索・
  サジェスト・CCS 等は本クライアントの対象外（再調査もしない）。

## パーサー由来の制限（第16ラウンドから引き継ぐ）

- 実測ページに広告結果が存在しなかったため、広告分離は
  合成フィクスチャでの検証まで。実広告HTMLでの検証は未実施。
- 天気カードの詳細値（気温など、canvas描画）とAI回答カードの
  本文は静的HTMLに存在せず取得できない。
- 日付は表示文字列のまま（年を持たないため絶対日付化しない）。
- 未観測の tpl は推測せず unknown_elements に記録される。
- タイトルはサーバ格納文字列のまま返す（WAF画面タイトルが
  結果タイトルになっている実測例がある。本クライアントでは
  警告を付けるが値は補正しない）。

## クライアント実装上の制限

- 検証ページ判定はマーカー（wappass 参照・安全验证）と
  `#results` の有無によるヒューリスティクス。サーバ側の
  検証ページ形式が変われば検出できない可能性がある。
- 本文上限（既定8MB）を超える応答はエラーとして中断する
  （部分パースはしない）。
- リトライは一切しない。失敗した検索の再実行は呼び出し側の判断。
- 重複判定は完全一致URLのみ（パラメータ違い・表記ゆれは別結果
  として扱う。これは意図的な仕様で、過度な正規化による
  誤統合を避けるため）。
- `search()` はページ単位の失敗を例外にせず diagnostics に
  記録する設計。失敗を例外で扱いたい場合は `search_page()` を
  ページごとに呼ぶこと。
- プロキシは requests の環境変数ベース設定に従う。プロキシ側で
  終端される場合、最終到達IP等は観測できない（従来どおり）。
- 実通信の検証は「天气」の最大2ページまで（指示された最小限）。
  大量ページ取得時のサーバ挙動は未検証。
