# 既知の制限事項

> baidu_parser 1.0.0 / 2026-10-26

## 実測範囲の制限

- 検証に使ったHTMLは2026-10-25取得の5ページ（天气×3、札幌 天気、
  weather）のみ。クエリによっては未観測の tpl が現れうる。
  その場合は推測分類せず `unknown_elements` に記録される。
- arm64版APKや異なるアプリ版数ではHTML構造が変わる可能性がある
  （対象は 15.57.1.10 の wise 版HTMLのみ）。
- ニュース専用tpl・画像単独結果tpl は実測で未確認のため、
  専用の分類は実装していない（現れる場合は未知として記録される）。

## 広告

- 実測サンプルに広告結果が含まれなかったため、広告分類は
  ページ同梱CSS（ec_ls_css）の規約＋可視ラベルに基づく実装で、
  検証は合成フィクスチャのみ。実広告HTMLでの検証は未実施。
- 広告が ec 規約と異なる形式で配信された場合、分類できない
  可能性がある（その場合 tpl が www 系なら通常結果として
  分類されてしまう点に注意）。

## カードの詳細度

- 天気カード: 気温・予報・チャートは canvas / chart モジュールで
  描画され、静的HTMLのテキストからは構造化できないため、
  見出しとリンクのみ抽出（本文は null）。
- AI回答カード: 回答本文は静的HTMLに存在しない（動的生成）。
  AI生成の明記フラグのみ記録し、本文は生成しない。
- ナレッジ/百科カードの `text` は説明文アンカーのテキストに依存。
  レイアウト変種では取得できない場合がある。
- 動画・ライブ・公式アカウント等のカード内 `items` は
  アンカー列挙に基づくベストエフォート（タイトルとクリックURLのみ。
  投稿日時・再生数等は分離していない）。
- note カードは複数ノートの集合で、items に各ノートのタイトルが入る。

## フィールドの癖

- タイトルはサーバが格納した文字列そのもの。実測では
  対象サイト側の事情で「WEB 应用防火墙」（WAF画面のタイトル）が
  そのまま結果タイトルになっている例があり、パーサーは
  HTML記載どおりに返す（補正しない）。
- 概要文の先頭に動画時間等のラベル（例「01:30」）が混ざる場合がある。
  `prefix-time` 要素の日付ラベルは分離できるが、それ以外の
  ラベルは summary-text 内に含まれるため分離しない。
- `data-click-info.extra.url` 由来の URL にはサーバ側の
  エンコード癖（`&#` 等）が残る場合がある（原文どおり保持）。
- 日付は表示文字列のまま（「10月25日」「4小时前」等）。
  絶対日付への変換は、取得年がHTMLに無いため行わない。
- サイト名は source の s-data（sourceData.text）に依存。
  s-data が無い結果では null になる（表示ドメインで代用しない）。

## その他

- パーサーはHTTP送信を行わない。HTMLの再取得は既存の通信コード側の
  責務であり、本パッケージには含めていない。
- 順位はHTML記載の `order` を信頼する。サーバ側の並び替えや
  パーソナライズの再現は行わない。
